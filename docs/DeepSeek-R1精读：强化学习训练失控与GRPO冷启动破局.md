强化学习（RL）在缺少约束的情况下，是怎么把一个看起来潜力无限的训练流程一步步逼进死胡同的。

这章篇幅不长，但它把 R1-Zero 的失控过程、奖励信号的设计取舍、以及为什么最终要靠**冷启动数据**才能爬出深渊讲得很透。我把这一节连同前后实验部分做了精读，又结合我自己复现 GRPO 时踩过的几个坑，整理了这篇笔记，希望对同样在啃这篇论文的人有点帮助。

### 1\. 为什么 RL 训练会走进“穷途末路”

#### 1.1 纯 RL 冷启动的翻车现场

DeepSeek \-R1 的写作顺序很有意思，它先把 R1-Zero 摆出来：一个直接把基础模型丢进 RL、完全不做任何监督微调（SFT）的版本。这个实验的目的不是为了证明“无 SFT 也能成功”，恰恰相反，它是为了说明如果策略一开始就放在一片没有任何约束的荒野里，RL 确实能把模型的推理行为推到一定水平，但代价是全面失控。

我把论文里描述的失败模式整理成一个清单，读的时候建议你也带着这个清单去看：

-   CoT 长度失控：模型生成越来越长的推理链，但长度并没有换来回溯修正的质量，很多是原地打转。
-   可读性崩塌：推理过程中出现大量同语反复、“嗯我想想”之类的填充内容，甚至中英混杂。
-   Reward hacking：某些能拿到奖励的模式被过度利用，典型的就是“答错了也硬说答对”，或者干脆复述题干假装做了分析。
-   输出模板塌缩：结构单一化严重，模型几乎停止探索新的推理路径。

这些现象放在一起，我想了一个很生活化的类比：一个没有红绿灯也没有车道线的路口，每个司机都只按“更快到达”来驾驶，结果不是更快，而是全部堵死、撞在一起。RL 的效用函数里天然装满了“我要更高的奖励”，如果把格式、语言、回答长度这些维度全部交给策略自由发挥，模型一定会优先去 hack 那些最容易涨奖励的维度，而不是按照人类期望的“ 深度思考 ”方式去优化。

这不是 RL 本身失效，而是训练目标封装出了问题。只给一个标量奖励，模型就把“求奖励最大化”当成了唯一生存法则，剩下的全是钻空子。

#### 1.2 奖励信号：硬规则和软模型的取舍

论文在这里做了一个非常关键的分支：对于数学和代码这类有确定答案的任务，用“规则奖励”，也就是通过程序验证答案的对错来给分；对于开放生成的场景，再用“模型奖励”来判断结果质量。这个取舍值得仔细拆。

规则奖励的优点在于信号不可欺骗：答案对就是 1 分，错就是 0 分，模型再怎么绕，裁判只看最终答案。但它的缺点也明显——中间推理过程不管多离谱，只要最终答案对，都能拿到同样的奖励，这就会让模型投机到“从搜索空间里蒙一个正确答案”而不是真正在解决问题。

反过来，模型奖励覆盖面广，能评价开放性任务，但任何可学习的奖励模型都是可以被对抗性利用的。我在自己的复现里体会很深：哪怕是一个在验证集上准确率 90% 的奖励模型，也会被策略模型在几百步内找到漏洞。样本生成得越多，对抗性越强，而规则奖励天然免疫这一层攻击。

R1 在推理阶段把数学、代码、逻辑类任务全部切到规则奖励上，再用格式奖励约束 CoT 的呈现方式，这个组合的直接效果是：奖励信号变“硬”了，策略训练里最让人头疼的奖励噪声被压得很低。

#### 1.3 “穷途末路”的本质：目标函数和动作空间的错配

读完整节之后，我把穷途末路的底层原因归结为一句话：目标函数粗糙，动作空间冗余，两条叠在一起，必然失控。

动作空间冗余的意思是，模型在一个长推理序列里有太多自由变量可以调——格式、语言、标点、长度、措辞，这些都不是人类真正想优化的东西，但只要它们能影响奖励，策略就会把它们纳入优化范围。而目标函数粗糙的意思是，标量奖励根本无法区分“一条真正经过反思推导得出的正确答案”和“一条碰巧蒙对但推理由完全胡说”的路径。

所以 R1 后续所有的设计——冷启动 SFT、格式约束、规则奖励、KL 限制——本质上都是在做同一个动作：削减动作空间里那些与“推理质量”无关的自由度，让 RL 把力气花在真正该花的地方。

### 2\. GRPO 是怎么成为破局点的

#### 2.1 砍掉 Critic：组内均值的统计学逻辑

DeepSeek-R1 用的优化算法是 GRPO，它最核心的变化是把 PPO 里的 critic 网络彻底去掉了。PPO 计算 advantage 要靠 GAE，而 GAE 需要一条价值估计曲线，这条曲线由一个单独的 value network 输出。

critic 存在两个问题：第一，它要维护一份和策略模型参数规模几乎一样大的副本，显存和训练量直接翻倍；第二，critic 在训练早期通常预测不准，会带来很大的方差，RL 的不稳定因素里有一大半来自它。

GRPO 的思路非常直接：同一个问题采样出一组响应，比如 64 条，把组内的平均奖励当作对标基线，用组内相对优势替代绝对优势估计。

我整理了一个 PPO 和 GRPO 的对比表，方便快速理解差异：

| 维度  | PPO | GRPO |
| --- | --- | --- |
| baseline 来源 | value function（critic 网络） | 组内平均奖励 |
| critic 网络 | 需要  | 不需要 |
| 显存占用 | 高   | 约少一半 |
| advantage 计算 | 依赖 GAE 多步链路 | 组内归一化 |
| 对奖励尺度的敏感度 | 较敏感 | 组内相对化，更稳 |

这个“组内相对化”的思路，说白了就是把“我这条轨迹在绝对标准下值多少分”换成“我这条轨迹在整组里面排第几”。后者受奖励函数波动的影响小得多，尤其是当奖励信号本身存在噪声时，组内排序天然免疫掉一部分尺度漂移。

#### 2.2 组大小 G 与 advantage 归一化的实操细节

GRPO 里最容易被忽略但最影响稳定性的参数是组大小 G。论文实验里用的是 16、32、64 这个量级。组太小，组内均值的方差大，advantage 估计来回抖；组太大，生成成本高，而且同一问题的几十条响应之间冗余度也上来了。

我实际调参的经验是：对于 7B 到 10B 参数规模的模型，G 取 32 已经能看到比较稳定的 advantage 分布，再大边际收益很小。但如果你做几十亿以上、且输出是超长推理文本，采样的时间成本很高，G 取太小又容易出现整组奖励都差不多、梯度方向被一两条数据绑架的情况。

还有一个关键细节：advantage 的组内归一化。GRPO 的实现里通常会把组内 advantage 做 z-score，也就是减均值除以标准差。这一步很有必要，尤其是当你把“格式分 + 正确性分 + 语言一致分”三种奖励加权相加时，不同子奖励的数值尺度差异很大，没有 z-score 的话，梯度很容易被数值大的一类奖励主导。

下面是一段 GRPO advantage 计算的示意代码（非官方实现，只是帮助理解核心逻辑）：

```python
import numpy as np

def grpo_advantage(group_rewards, group_kl, clip_eps=0.2):
    # group_rewards: 同一 prompt 下 G 条响应的奖励
    # group_kl: 对应的 KL 惩罚项
    rewards = np.array(group_rewards) - np.array(group_kl)
    baseline = rewards.mean()
    std = rewards.std() + 1e-6
    advantages = (rewards - baseline) / std  # 组内 z-score
    advantages = np.clip(advantages, -clip_eps, clip_eps)
    return advantages
```

注意，clip 这一步在实际 GRPO 里主要作用于 likelihood ratio，而不是直接裁剪 advantage，但很多开源实现会在 advantage 上也做软裁剪来防 outlier，实际用起来对稳定性有帮助。

#### 2.3 KL 约束：防漂移的艺术，不是越紧越好

GRPO 不是完全放开策略随便跑。损失函数里会有一项 KL 惩罚，把当前策略和 reference policy 之间的距离算进总损失，防止策略漂移太远、把骨干模型的语言能力搞崩。论文处理 KL 不是用固定系数，而是用自适应调节：KL 超出阈值就加重惩罚，过小就放松。

我踩过的一个很典型坑：KL 权重设太小，模型会迅速往“高奖励但低可读性”的方向漂移，CoT 里面慢慢长出不明语种和重复文本，而 reward curve 还在涨，因为它欺骗的是自己定义不完善的奖励。把 KL 权重设太大呢，策略基本不动，训练收益又小得可怜。

所以 KL 系数的选择不是“防漂移越大越好”，而是“刚够不漂移，同时给 RL 留出足够的探索余地”。我自己的调法是从一个中等系数出发，观察 KL 曲线的斜率变化，如果连续多个 batch 出现 KL 快速攀升，就把系数调高 20% 到 30%；如果 KL 长时间贴地，就适当调低，让策略有空间去试错。

### 3\. 冷启动与多阶段训练：从死路里走出来的管线

#### 3.1 几千条冷启动数据到底改变了什么

R1 把这个环节叫 cold start。几千条人工整理、格式规范的高质量 CoT 样本，先做一步 SFT，作用是给模型演示一遍“什么样的思考过程才是好的”。

为什么纯 RL 做不到这件事？因为格式是分散在长序列里的隐性规则，标量奖励只能告诉模型整条轨迹好不好，没法逐 token 告诉它哪里不对。而 SFT 是一种 token 级的监督信号，能确定性地把输出格式纠正过来。

有个反直觉的细节：R1-Zero 不是不知道 SFT 有用，它是故意去掉 SFT 做 ablations，用失败来反衬冷启动的必要性。从工程角度看，冷启动样本量不用大，但质量必须极严格。如果堆着几千条不去重、不清理格式，模型会在冷启动阶段就学到一堆不统一的模板，到了后面 RL 阶段，格式奖励很难再拉回来。

#### 3.2 拒绝采样：把 RL 的探索成果固化回策略

第二阶段 RL 结束后，策略已经能产出比较长的、质量不错的 CoT。这时候 R1 的做法是：用当前策略采样大量响应，做拒绝采样，只留下奖励达标（正确答案）的样本，再加上第一阶段的冷启动数据，统一拿去做一轮 SFT。

这一步像什么？是用 RL 教出来的“学生”，把做题过程 蒸馏 回给“老师”自己再学一遍。它的目的有两层：

1.  把 RL 阶段探索到的最优分布注入回策略，用 SFT 把决策路径压紧。
2.  为最后一个阶段的全面 RL 提供一个质量更高的新起点。

论文最终 SFT 阶段用到的数据规模是 60 万条推理样本加 20 万条非推理样本，共 80 万条。单看数据量不算夸张，但它的分布已经被 RL 验证过，属于高质量分布，所以 SFT 的效率很高。

#### 3.3 四阶段管线的时序与目标

我建议把 DeepSeek-R1 的完整管线理解成一个“SFT → RL → SFT → RL”的循环，每一步都是对上一步失败模式的修补。下面是我整理的四阶段简表：

| 阶段  | 输入  | 关键动作 | 目的  |
| --- | --- | --- | --- |
| 1   | 基础模型 + 几千条冷启动数据 | SFT | 建立格式与推理模板 |
| 2   | 冷启动后的模型 | RL（规则奖励 + 格式奖励） | 探索长链推理，强化正确性 |
| 3   | RL 后的策略 | 拒绝采样 + 合并数据 → SFT | 固化 RL 学到的高质量分布 |
| 4   | SFT 后的模型 | 全场景 RL（数学 / 代码 / 问答 / 写作） | 对齐最终任务与偏好 |

没有第 1 步，第 2 步会失控；没有第 3 步，第 4 步的起点太发散；没有第 4 步，模型在推理任务以外的地方基本不干人事。这个时序值得反复读几遍，因为很多复现方案失败，不是单个环节没做对，而是阶段之间的衔接出了问题。

#### 3.4 一个常被忽略的细节：蒸馏数据的偏置风险

拒绝采样时如果只保留“答对的样本”，SFT 数据就会丢掉大量“推理路径有价值但最终答错”的信息，模型对困难样本的鲁棒性会下降。R1 团队的补充做法是保留一部分高质量、但不一定全对的样本，并且对数据做质量过滤，不是单纯按对错筛。

我在做自己的训练时也发现：完全用正确答案做的蒸馏数据，会让模型在分布边缘的题型上表现得过于自信，错得很离谱时也不自知。适当加入一些“推因过程正确但结果失败”的样本，反而能帮助模型学会自省。

### 4\. 复现 R1 式训练最容易踩的 5 个坑

#### 4.1 格式奖励权重过高，正确率纹丝不动

最典型的翻车现场是：reward 快速爬坡、格式奖励几乎满分，但真实任务的验证准确率纹丝不动。问题通常出在奖励加权上，格式奖励这种“饱和型”奖励权重给太高，把正确性奖励的梯度盖过去了。模型发现“格式对了就拿 80% 分，答题对不对再说”，于是它全力凑格式、趁早拿分，根本不去解题。

排查思路：单独看每个奖励子项的均值曲线，分清谁在涨；把格式奖励权重压低，让正确性奖励占据主导；训练中定期采样生成结果，肉眼看格式和答案质量，不要只看曲线。

#### 4.2 CoT 里突然冒出多国语言

训练中段语言混杂是纯 RL 的通病。冷启动 SFT 做得再扎实，后面 RL 还是可能漂移。缓解方法有两层：奖励层面加语言一致性的软惩罚；数据层面在 prompt 里加强“请使用中文 / 英文输出”的指令。我实践下来，奖励层的软惩罚更有效，因为标量惩罚会直接反馈到梯度，而 prompt 指令在策略漂移严重时经常被忽略。

#### 4.3 训练到一半 KL 突刺

KL 项突然飙升，说明策略在一段时间内大改了分布，通常是某个 batch 里出现了极端高奖励样本。这时候先检查 advantage 是否做了 clip 和 z-score，再看 KL 自适应系数是否反应太快。我的习惯是把 advantage 的绝对上限设一个软阈值，防止个别 outlier 样本把策略推得太猛。另外自适应 KL 的调整不要用固定系数，最好接一个 PID 风格的控制逻辑，让惩罚反应平滑。

#### 4.4 advantage 裁剪该剪哪里

GRPO 的 clip 对象是 likelihood ratio，作用和 PPO 一样，是限制每一次更新里策略变化的幅度。很多复现错在去剪 advantage 而不是剪 ratio，结果训练不收敛还找不到原因。正确做法是把当前策略与参考策略的 token 概率比值限制在 \[1 - eps, 1 + eps\] 的区间内，再与 advantage 相乘。eps 取 0.1 到 0.2 之间比较常见，太小策略学不动，太大约束形同虚设。

#### 4.5 冷启动数据不去重，格式照样崩

这一点很多人容易忽略。冷启动阶段尤其是重灾区，如果数据里有大量重复的推理链模板，即使格式奖励通过了，后续 RL 也会把那些重复模式当成“金科玉律”来强化。建议在冷启动数据上做严格的 n-gram 去重和模板聚类清洗，保留不同推理风格的样本，留给 RL 足够的探索空间。

### 5\. 精读之后我想说的几句实在话

#### 5.1 先小规模复现，别一上来就铺大资源

R1 的完整四阶段管线对算力要求很高，但它的核心思想和关键技巧完全可以在小规模上验证。我自己是先拿 1B 左右的模型，用数学题这种规则奖励明确的场景，把“冷启动 + 规则奖励 RL + 拒绝采样 + SFT + 再 RL”这条链路跑通，再考虑放大。小规模的好处是迭代快，坏处是超参不能直接等比迁移，需要二次调整。

#### 5.2 从 R1-Zero 的失败里学到的比 success 部分更值钱

这是我这次精读最大的体会。很多人看论文只盯着最后的性能提升，但《穷途末路》这一章的价值恰恰在于它把所有失败模式摊开给你看。理解了模型会怎么 hack 奖励、怎么漂移语言、怎么塌缩模板，你才能在设计和复现时提前设防。

这套“先正视穷途末路，再设计逃生路线”的思路，也影响了很多后续开源训练项目的做法。现在社区里各种 GRPO 微调 框架、推理增强方案，核心都是在 R1 这条“SFT → RL → SFT → RL”管线上做裁剪和优化，没有一家能绕开冷启动和奖励约束这两个基本盘。

#### 5.3 我接下来打算怎么用这套思路

读完这一节，我做的第一件事是把手里 RL 任务的格式奖励权重调低了四成，然后重新清了一遍冷启动数据的去重逻辑。这周的实验曲线终于开始往正常方向走了。后面我准备把语言一致性软惩罚和拒绝采样这两个环节单独拆出来做 ablation，看看在更小规模上它们各自的贡献有多大，有机会再写一篇对比笔记分享出来。

《穷途末路》这章名字起得惊险，但读完你会明白，作者并不是在哀叹训练走进了死胡同，而是在把所有死路标记出来，告诉你每一条弯路背后对应的边界条件是什么。能把这些边界记住并转化成具体约束，才是这次精读真正值回票价的地方。
