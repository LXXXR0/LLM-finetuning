## 一、项目需求
定位：
目的：三元组（实体A，关系，实体B）-文档能对应起来，以实现证据溯源
数据情况：
（1）对已有准确知识图谱（knowlede console上直接能导出三元组的数据），gold关系：图谱里已存在的edges，回标到文本
（2）根据ontology定义（只有类型schema，没有实例图谱），按ontology定义，从文本抽取出关系。

## 二、数据层面
### 注意点
（1）防泄露，train和validation层面防泄漏；（2）数据长度，各长度切分；小样本实验：长度要和训练预算匹配，否则引入阶段噪声。训练前可以先做length审计，超长的报错/丢弃。

## 三、算法层面
（1）SFT loss口径：默认整条序列算loss（含prompt+那段超长schema/ontology定义）。system + user prompt巨长（光schema就占大量token），整条算loss会让模型的梯度被prompt主导，真正该学的answer信号被稀释。—— 可以completion-ony只在答案上算loss，信号干净。
（2）训练/推理/评测用的prompt要保持一致。
