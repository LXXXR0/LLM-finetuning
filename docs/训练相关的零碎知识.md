系统梳理一遍 LLM 微调（SFT / LoRA / RL）里你日常会碰到的全部参数、配置、概念，分成四大块：【训练循环基础参数】、【优化器 & 学习率系列】、【LoRA / 微调模式配置】、【正则 & 防过拟合配置】，最后补充 RL 阶段额外参数。


## 训练循环基础参数（epoch/step/batch）

batch_size: 一次喂给模型多少样本；
epoch：把整个训练集完整跑一遍；
lr（学习率）：梯度每一步迈多大；
梯度更新：用损失的梯度，反向调模型参数

### batch_size批次大小
一次前向 + 反向传播，同时计算多少条数据

batch_size = 8：一次拿8条样本，一起算loss、算梯度；
微批次(micro batch)、梯度累积(gradient accumalation)：

>很多大模型显存不够，不能直接开大batch：
>  真实有效batch = batch_size × gradient_accumulation_steps
>  比如：bs = 2，累积4步：每4次算完梯度再更新一次参数，等价bs = 8
bs越大：梯度估计越稳，训练震荡越小；显存占用暴涨；
bs越小：梯度噪声大，泛化有时候更好；省显存。

### epoch轮数
一个epoch = 全部训练数据，完整遍历一轮

epoch = 1：所有样本只看一遍；
epoch = 3：数据集从头到尾过3遍。

很多SFT只训1epoch，甚至0.3-0.7epoch，多训容易过拟合（背诵训练集、泛化变差）—— 这里就是让它过拟合，后面再用RL和OPSD做泛化能力的提升。

### gradient_accumulation_steps 梯度累积步数
连续跑N个micro batch，只累加梯度，不更新参数；攒够N次之后，才做一次optimizer.step()

有效batch = micro_batch_size x gradient_accumulation_steps
 - 作用：用小显存，模拟更大batch的梯度（梯度更稳定）；
 - 注意：梯度累积不会降低显存峰值，只是等效放大 batch；和梯度检查点（gradient checkpointing）是两回事

### gradient_checkpointing 梯度检查点
-牺牲一点点训练速度，大幅省显存。
-原理：前向的时候不存全部中间激活值，反向的时候重新计算。

### max_seq_len / context window

序列最大长度；
输入 + 输出的token总和不能超过这个值；超长会截断。
- 截断位置很关键：是截上文，还是截答案？不同框架行为不一样
- 越长，单条样本显存占用越高

### packing / 序列打包
把多条短样本拼在一起塞到同一个 seq 里，减少 padding 浪费，提升效率。

### dataloader shuffle

每个 epoch 前打乱样本顺序。

- 一定要开：避免模型按样本顺序学到位置偏见
- 不开的话，梯度时序相关，震荡很大


> 注意：step步数和epoch区别
>   step= 一次参数更新
>   total_steps ≈总样本数 / 有效batch_size × epoch

## 二、优化器 & 学习率整套

### optimizer 优化器

LLM 微调几乎固定用 **AdamW**

- Adam：自适应学习率，给每个参数单独算更新步长，适合大模型
- AdamW：在 Adam 基础上，**把 weight decay 和梯度解耦**（重点！）

> 老 Adam 的 weight decay 是错的，现在所有 SFT/RL 默认 AdamW，不要用 SGD，除非你有特殊需求


### lr学习率learning rate
梯度下降的步长：
  <img width="157" height="21" alt="{80D36528-CF21-4AE2-9CB3-4F908011B958}" src="https://github.com/user-attachments/assets/092580e3-96a3-40bb-a1e7-069e57384ea9" />
  - lr 太大：参数蹦来蹦去，loss 震荡不收敛，甚至 NaN 炸掉
  - lr 太小：学习极慢，卡在局部低点，训很久没效果
    
配套常见策略（你训 LLM 一定会碰到）：

1. **warmup 预热**：前几千步 lr 从小慢慢升到峰值 lr，防止刚开始梯度爆炸
2. **lr decay 衰减**：后面 lr 慢慢降下来（余弦 cosine / 线性衰减），后期精细微调

> 典型 SFT：peak lr = 2e-5 ~ 5e-5；LoRA 一般比全参数微调 lr 高一点，比如 3e-4


### lr_scheduler 学习率调度器

lr 不是固定不变的，主流两种：

1. **cosine 余弦退火（最常用）**：warmup 升到峰值，然后余弦曲线慢慢降到 0
2. linear 线性衰减：升到峰值之后，线性降到 0
还有 constant（固定 lr，几乎不用，后期容易不稳定）

### 4. warmup_steps /warmup_ratio 预热

训练最开始的一小段 step，lr 从 0 慢慢升到 peak lr。

- 为什么要 warmup：刚开始模型权重是基座权重，梯度方差很大，直接大 lr 容易梯度爆炸、loss NaN
- 常用：warmup_ratio=0.05，也就是前 5% 的 step 用来升温

### 5. weight_decay 权重衰减

给参数 L2 惩罚，**惩罚大权重**，抑制过拟合。

- 不是 dropout！它是在优化器更新的时候起作用
- AdamW 里典型值：0.01 ~ 0.1
- 注意：bias、norm 层参数一般**不做 weight decay**，框架会自动分开

### 6. max_grad_norm 梯度裁剪 gradient clipping

把梯度的二范数限制在这个上限以内。

- 作用：防止**梯度爆炸**（梯度一下子变得巨大，参数直接飞掉，loss 变成 NaN）
- 典型：max_grad_norm=1.0

> 
> 梯度消失 LLM 靠残差 + 归一化天然缓解，一般不用你手动处理；梯度爆炸靠这个参数兜底



# LoRA 微调专属配置（你做 SFT 最常用）

> 
> 区别于全参数微调：只训练低秩矩阵，基座权重冻结，显存省很多

1. **lora_rank (r)**
LoRA 矩阵的秩，**可学习参数的容量核心**

- r 越大：可表达能力越强，越容易记住训练集（过拟合风险↑）；r 越小，容量有限，不容易背，但能力上限低
- 常用：8 / 16 / 32

2. **lora_alpha**
缩放系数，一般设成和 r 一样，或者 r*2

\(缩放 = \frac{alpha}{r}\)
本质是控制 LoRA 更新的幅度，和 lr 配合调节
3. **lora_dropout**
LoRA 分支内部的 dropout，抑制过拟合，0.05~0.2
4. **target_modules**
指定哪些 transformer 层开 LoRA。
Qwen 一般打 attention 的 q_proj、k_proj、v_proj、o_proj；有的会加上 mlp 层。

> 
> 只训 qkv：省显存；加上 mlp：拟合能力更强，更容易过拟合

5. bias：是否训练 bias，一般设成 none，不训 bias
6. merge_lora：训练结束后，把 LoRA 权重合并进基座，推理的时候不用单独加载 adapter

# 四、损失、掩码、正则、评估相关

### 1. loss_mask / attention_mask

- attention_mask：告诉模型哪些是 padding，不要看
- loss_mask（SFT 里最重要）：**只计算回答部分的 loss，prompt 部分不计算 loss**

> 
> 很多新手 bug：prompt 也参与 loss 计算，模型学会去预测指令，直接学废

### 2. loss 损失函数

SFT 标准：**交叉熵 CrossEntropyLoss**，下一个 token 预测

- label smoothing 标签平滑：正则手段，不让模型对标签过度自信，降低过拟合，0~0.1 之间

### 3. early_stopping 早停

监控验证集指标（dev loss /dev F1），patience=5：连续 5 轮验证集指标不涨，直接停止，保存最优 checkpoint。

> 
> 小数据集 SFT 的第一大防过拟合神器，比调参数还管用

### 4. dropout

随机让一部分神经元输出置 0，强制模型不要依赖少数特征。
基座原生 dropout，微调时可以开；LLM 里一般不大，0.05~0.1。

> 
> 注意：dropout 在 eval 评估模式下自动关闭，评估的时候不会随机失活

### 5. padding_side

padding 加在左边还是右边。
LLM 自回归生成，**padding 必须在左边**，不然会乱。

# 五、RL（GRPO/OPSD）阶段额外参数（你后面会碰到）

RL 是在 SFT 底座上做偏好优化，很多参数和 SFT 不一样：

1. **beta (KL 系数)**
KL 散度惩罚权重，控制新模型和 SFT 参考模型之间的距离。

- beta 大：贴近 SFT 底座，改动小，不容易崩，但很难修正 SFT 的坏习惯
- beta 小：改动空间大，容易模式崩溃、胡说

2. **num_rollouts**：每个 query 采样多少条回答
3. **reward_model / reward_fn**：打分函数，给生成结果算奖励
4. **ref_model**：用来算 KL 的参考模型（一般就是你的 SFT 底座）
5. cliprange：PPO 里的裁剪；GRPO 简化了，不需要 PPO 那套 clip

# 六、补充几个高频容易混淆的概念（不是参数，但天天提到）

1. **冻结（freeze）**：参数不参与更新，梯度不计算
2. **可训练参数（trainable params）**：会被 optimizer 更新的权重
3. checkpoint：模型权重快照，保存中间状态，可以断点续训
4. resume_from_checkpoint：断点续训，不光加载权重，还要加载优化器状态、scheduler 步数，保证学习率曲线连续
5. 混合精度 fp16 /bf16
   - fp16：容易溢出，需要梯度缩放
   - bf16（推荐 LLM）：范围更大，不容易 NaN，现在 A100、RTX40 系都支持 bf16
   作用：降低显存占用、加速训练





### 梯度更新（反向传播）
（1）输入batch样本 → 模型前向推理 → 算出预测和标签的loss
（2）反向传播：链式法则，求 loss 对每一个参数的**梯度 gradient**（告诉我们参数往哪个方向改能降低 loss）；
（3）**梯度累积模式（可选）**：连续多个 micro batch，把梯度累加，暂时不更新参数
（4）到达累积步数 → 优化器（AdamW）用梯度、lr，更新权重
（5）梯度清零，下一轮

重点区分两个东西：

- **梯度计算**：每次 forward+backward 都会算，占用显存
- **参数更新**：只有当累积够步数、调用 optimizer.step () 才发生
 
> 梯度累积就是：**多次算梯度，一次更新**


### 举个完整例子

数据集一共 1000 条；
`batch_size=4，gradient_accumulation_steps=2，epoch=1`

- micro batch：4 条
- 有效 batch：4×2=8
- 一轮参数更新消耗 8 条样本
- 1 epoch 总 step = 1000 / 8 = 125 step
